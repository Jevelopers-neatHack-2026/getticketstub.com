# APP-REVIEW-003: local fact identity and source boundaries

Reviewed predecessor: `4883b9ea2a9460ffad7edcd80d356789a5e9c837`, PR #209. This follow-up implements the [2026-10-12 Product decision on #94](https://github.com/Jevelopers-neatHack-2026/getticketstub.com/issues/94#issuecomment-6126131742). It supersedes the earlier candidate's incorrect source-ID suffix repair. It does not establish Product or canonical acceptance.

`Fact.id`, source, source URL and provenance remain as received, including repeated and empty IDs. Normalization allocates an opaque `ce_<UUID>` in a separate `Fact.clientEntityKey`; valid unique keys are reused. Duplicate local keys are replaced for every colliding row, leaving their old history references unresolved rather than choosing a first winner. No label, content hash or row index allocates entity identity. Existing `note-2` source values are preserved: this code cannot infer whether an already suffixed ID came from the source or a predecessor development build, and does not guess a reverse mapping.

Fact rows, receipt selection state, local inclusion, chips, measured fit, question targets, corrections and undo use the persisted entity key. A question and new correction retain the source ID separately. Reordering therefore does not move the action to another source occurrence. Historical parameter names such as local `toggleKept(..., factId)` accept the entity targeting token; they are not canonical FactId ports. Current-project toggle guards and globally distinct keys reject foreign or stale local actions. New corrections append both the original source ID and local target; old correction entries are never rewritten. A legacy source-only correction binds only if exactly one fact has that source ID. Inconsistent source/key history also stays unresolved and produces the review warning.

Legacy hidden-field presentation previously hid every row sharing a source ID. That visibility state is expanded to all corresponding local keys without selecting a winner; static title/subtitle/art/group hiding remains static. This is a visibility-preserving presentation migration, not assignment of ambiguous correction history. A subsequent explicit inclusion action changes only its selected row. Newly generated keys remain stable in memory for repeated reads of the same legacy wall even if the migration cannot be written. Failed writes still return false and retain the existing unsaved/sync recovery UI. No successful persistence is claimed for that case.

## Serialization inventory

| Boundary | Disposition |
| --- | --- |
| Local wall, account wall JSON/SQLite, local versions and legacy share encoding | App-owned persistence deliberately retains the separate client metadata and local references, to support reopen/account sync. It does not rename `Fact.id`. Decode/ingestion normalizes older inputs. |
| App-owned public share DTO (`src/server/project.ts`) | Explicitly retains a bounded, validated client key for display identity and the associated local hidden fields; corrections, photos and private personalization retain their existing privacy projection. This is an app display DTO, not a canonical research package. |
| Research-to-client event DTO / printing input | App-owned ingestion normalizes once and retains keys through the printing selection and final draft. Source/provenance values are unchanged. |
| Art and legacy text-agent requests (`research/client.ts`) | `sourceEvent` explicitly omits client metadata from each fact. The art route independently allowlists the prompt fields. Legacy text-agent prompts read explicit source/content fields only. |
| Typed agent action summary | Explicit source-field allowlist omits local metadata and omits facts whose source IDs are ambiguous. Agent keep/unkeep refuses an ambiguous source target; no local key is exported as a model-facing canonical ID. |
| Creative brief, brief-create, dynamic controls, edit plans | Reject duplicate, empty or local-looking source IDs with the **local** `FactIdentityMappingError` (`fact_identity_mapping_required`) before emitting a foreign DTO. For existing unambiguous source identities, translate local edit/hidden targets back to their original source IDs. No canonical schema, enum, SDK pin or authenticated producer mapping is invented. Existing proposal/PENDING limitations still apply even for unambiguous IDs. |
| App approval/source hashes | Fact projection explicitly selects original source/content fields. Personal and version-snapshot hidden targets project to the unique original source ID, preserving existing unique-source approval bindings; duplicate targets project to app-owned source/content digests, never random client keys. These digests are hash inputs, not entity keys or canonical FactIds. Unresolvable local hidden references project to an explicit unresolved marker. Approval-summary lines retain their existing source/content-only wire shape. |
| Order/approval tokens | Carry the resulting app-owned hashes, not the client entity metadata. No new token fields or canonical identity claims. |
